Исходная проверка: **1 октября 2026**, часовой пояс Asia/Makassar. Проверка выбора сервисов через профили — **23 октября 2026** (ниже).

Полная цепочка выполнена в Docker: **Postgres → Airflow → Greenplum raw → dbt staging → core → marts**. Готова одна витрина `marts.mart_sales_daily`; две остальные остаются заданиями.

Логи этого этапа сохранены в `artifacts/profiles-*.log`. CI обновлён: базовый режим → источник → полный DWH → проверки данных → перезапуск → возврат к базовому режиму. GitHub Actions в этом этапе не запускался; Windows и отдельная Linux-машина здесь не проверялись.

После проверки удалены только контейнеры и тома тестового проекта `localstand-profiles-check`. Colima возвращена в исходное остановленное состояние; основные учебные тома сохранены.

Во время первого подключения источника на текущем Mac обнаружены облачные файлы-заглушки (`compressed,dataless`). Контейнер не смог прочитать init SQL: `Resource deadlock avoided`. После полной загрузки файлов на хосте чтение из контейнера восстановилось. Повторён старт с новым **только тестовым** томом источника; seed и проверки прошли. В README и сценарий добавлена диагностика такого состояния файлов. Успешный первый запуск источника требует доступного локального содержимого SQL; повторный `up` после неудачного init не пересоздаёт уже инициализированную базу.

## Окружение

- Mac с Apple Silicon, 16 ГБ RAM.
- Docker Engine 29.5.2 в Colima 0.10.3; Compose 5.5.1.
- Отдельный профиль `localstand-dwh`: Linux arm64, 4 CPU, 8 ГБ RAM, диск 30 ГБ. Контекст Docker: `colima-localstand-dwh`.
- PostgreSQL 16.6, Greenplum 6.27.1, Airflow 2.10.5 / Python 3.10.
- dbt Core 1.5.11, dbt-postgres 1.5.11, dbt-greenplum 1.5.0 — отдельное окружение внутри Airflow-образа.

Docker отсутствовал на машине; для проверки установлены Docker CLI, Compose, Buildx и Colima. Основной стенд запущен нативно на arm64. Дополнительно собран и запущен отдельный стенд Linux amd64 через QEMU на том же Mac; его порты и тома изолированы от основного проекта.

При первой инициализации Colima временный сбой DNS помешал установить служебный `rsync`. Пакет установлен после восстановления сети. После полного перезапуска виртуальной машины cloud-init завершил настройку без ошибок выполнения, упавших системных служб нет. Предупреждения cloud-init об устаревших именах полей в конфигурации Lima на работу стенда не влияют.

До финального сброса учебных данных выполнено **семь успешных DAG-запусков**: один автоматический и шесть проверочных. Первый занял 24 секунды после старта scheduler, повторные — около 14–17 секунд. Загрузка образов и инициализация контейнеров в это время не входят.

В конце проверки удалены только созданные для этих прогонов учебные тома и повторён старт с пустыми базами. Восьмой DAG запустился автоматически и завершился успешно. Стенд оставлен включённым с исходными **400 заказами**, продажами **7 158 110 ₽** и пятью сервисами в состоянии `healthy`. `airflow-init` завершён с кодом 0 — это штатное состояние одноразовой задачи.

Затем проверен полный перезапуск Colima и Docker Engine: сервисы поднялись, ещё два DAG прошли с исходными контрольными значениями. Итого **10 успешных сквозных запусков**. Проверочный скрипт также ожидает готовности API Airflow, если его запускают сразу после `docker compose up -d`.

После изменений для переносимости выполнены ещё два успешных запуска на arm64. Все 11 моделей и 72 dbt-теста по-прежнему проходят; исходный набор сохранён.

## Переносимость и исправления запуска

- В замедленном amd64-прогоне первый старт webserver превысил стандартные 120 секунд. Число web-процессов уменьшено с четырёх до двух, таймауты увеличены до 300 секунд. После исправления при чистом старте webserver и scheduler получили `healthy` с нулём перезапусков.
- На исправленной конфигурации amd64 прошли автоматический DAG, два повторных запуска, все 72 dbt-теста и проверка отката COPY. Итог — те же 400 заказов и 7 158 110 ₽. Логи: `artifacts/amd64-clean-start.log`, `amd64-smoke.log`, `amd64-rollback.log`, `amd64-dbt-result.log`, `amd64-validated-runs.txt`.
- Scheduler проверяется через собственный HTTP healthcheck на порту 8974 внутри контейнера. Это убирает повторные запуски тяжёлого CLI-процесса для проверки здоровья. Используется [штатный механизм Airflow 2.10.5](https://airflow.apache.org/docs/apache-airflow/2.10.5/administration-and-deployment/logging-monitoring/check-health.html#scheduler-health-check-server).
- `.gitattributes` закрепляет LF. Проверен отдельный Git checkout с `core.autocrlf=true`: Dockerfile, Compose, SQL и shell-скрипт сохранили LF.
- Общие bind mounts используют `:ro,z` для совместимости с SELinux. На текущем Linux-движке эти монтирования проверены запуском; отдельного прогона на SELinux-хосте не было.
- README содержит подготовку macOS, Linux и Windows 10/11 через Ubuntu WSL2, затем общие команды. Ручное создание баз, Connections, DAG и загрузка данных не требуются.
- CI настроен на два нативных Linux runner: `ubuntu-24.04` и `ubuntu-24.04-arm`. Прогоны GitHub Actions ещё не выполнены.

**Граница проверки ОС:** здесь нет отдельной Windows 10/11 или Intel Mac машины. Проверка amd64-контейнеров под эмуляцией подтверждает работу образов и пайплайна на этой архитектуре. Интеграцию конкретной Windows с WSL2/Docker Desktop нужно подтвердить запуском на такой машине. Версии Windows и Docker должны соответствовать требованиям, указанным в README.

## Как повторить проверку

На исходном наборе данных:

```bash
docker compose --profile dwh config --quiet
docker compose --profile dwh up --build --detach --wait --wait-timeout 600
# Дождаться автоматического первого DAG и проверить результат:
docker compose exec -T airflow-scheduler python /opt/airflow/scripts/smoke_test.py --initial-only
# Проверить ещё два запуска:
docker compose exec -T airflow-scheduler python /opt/airflow/scripts/smoke_test.py
# Выполнять, когда другие DAG-запуски завершены:
docker compose exec -T airflow-scheduler python /opt/airflow/scripts/check_rollback.py

docker compose exec -T client-postgres psql -U postgres -d postgres -v ON_ERROR_STOP=1 < scripts/demo_changes.sql
docker compose exec -T client-postgres psql -U postgres -d postgres -v ON_ERROR_STOP=1 < scripts/demo_changes.sql
docker compose exec -T airflow-scheduler python /opt/airflow/scripts/smoke_test.py --expected changed

# Тома сохраняются:
docker compose --profile dwh down
docker compose --profile dwh up --detach --wait --wait-timeout 600
docker compose exec -T airflow-scheduler python /opt/airflow/scripts/smoke_test.py --expected changed
```

`--wait` ждёт готовности сервисов. Завершения DAG дожидается `smoke_test.py`; один только статус контейнеров не подтверждает готовность витрины.

На текущем Mac после остановки Colima её можно снова запустить:

```bash
colima start localstand-dwh
docker context use colima-localstand-dwh
docker compose --profile dwh up -d
```
